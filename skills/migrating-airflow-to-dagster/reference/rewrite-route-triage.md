# Triage of the 12 `different` rewrites (stage1)

Read from the workers' reports, the raw Airflow and rewrite results and the harness's per-dimension diffs under the evaluation work directory. "Re-computed" means the stored raw results of `stage1` were compared again with the changed harness (read only; `stage1` and its results were not modified): header parser fix, virtualenv baseline classification, and folded not-taken branches accepted as a representation difference. Nothing was re-run in Airflow or Dagster.

Lens: a `skipped` against `success` difference caused only by folding a not-taken branch into one asset is an **accepted representation difference** (Dagster has no state for code that is not run) when the side effects match and the decision record declares it. It is a **defect** when the state could have been expressed (the native optional-output form) or the effects differ.

| `fetch_extra_info` (`different`: tasks, failure) | `get_extra_triggering_run`: Airflow `failed`, rewrite `success` | the task is nondeterministic in Airflow itself: states across the four recorded runs were failed, success (kit run 2), failed, failed. Two more things the stricter loader exposed while re-running all 40 projects: a DAG with an interval schedule (`tutorial`) was asserted to have NO schedule (the old test only saw one module, so it passed by accident): interval, asset and custom timetables are now `unchecked`, like the behaviour comparison; and a project that holds another DAG's schedule is judged by the schedules of its own job.

## Stage 2a: the 9 `different` rewrites (60 DAGs, workers cold, two arms)

How read: **read** = from the worker's output, report and the stored Airflow and rewrite results (nothing re-run); **run** = executed on Dagster 1.13.31 (pattern fixes, each asserted in `tests/test_rewrite_patterns.py`) or re-computed with the changed harness from the STORED raw results of the measurement (`compare` over the stored Airflow and rewrite JSON and logs; `stage2a` itself was not modified and nothing was re-run in Airflow).

| DAG | Verdict now | Class | Evidence |
|---|---|---|---|
| `deltalake_example` | different (outcome, tasks, failure) | **baseline artefact** | read: Airflow's `print_deltalake_table` failed in the sandbox with `OSError: Repetition level histogram size mismatch` (a pyarrow / deltalake version problem of the baseline environment; not the DAG's logic), `delete` was `upstream_failed`. The worker's report names a different error (`stringify`): it was guessing, the log says otherwise. The rewrite ran all three steps successfully, a declared deviation (`failure semantics: not preserved`). The harness classed the baseline `by-design-failure` because the error text matches no known environmental pattern, so the gate demanded failure. Not fixable generically (an arbitrary library error cannot be recognised as environmental). |
| `example_branch_datetime_operator_3` | different (tasks, dependencies) | **real defect, pattern-library gap** (fixed) | read: the branch task `datetime_branch` was folded into the multi_asset and the header mapped it to `date_in_range`; when the run took `date_outside_range`, that asset was skipped, so the branch task read `skipped` (Airflow: `success`). The pattern showed branch outputs only (`outs={...: is_required=False}`), so the worker had no asset for the decision. The registry `conditional_asset` (mode branch) has the same shape: it exposes no asset for the decision. **Fix (run)**: `branching.py: decision_and_branches` (always-yielded decision spec + skippable branch specs in one `multi_asset`), documented in `branching.md`, claim in `index.json`, test `test_branching_decision_asset_is_materialized_every_run_and_only_the_chosen_branch_next_to_it`. Not re-run on the DAG itself (the worker's rewrite is unchanged); the rewrite stays `different` in the stored measurement. |
| `example_dag_decorator` | different (outcome, tasks, values, http) | **harness artefact + baseline artefact** (minor worker deviation) | read: the original calls an HTTP client (`httpx2`) that the sandbox does not intercept (it records `requests` and `urllib` only), so Airflow reached the real network and got a real IP; the worker replaced the client by `requests`, which the sandbox answers with `{"ok": true}`, so `origin` is missing and `get_external_ip` fails. Same code with the same client would have hit the real network on both sides. Not fixed: intercepting every HTTP client is a feature, not a bug fix; the value (a real IP) is nondeterministic across machines anyway. Worker point: swapping the client library changed what is observable (declared as `http client: not preserved`). |
| `example_short_circuit_decorator` | different (tasks, dependencies) | **real defect, pattern-library defect** (fixed) | read: `short_circuit` and `condition_is_false` ended `skipped` (Airflow: `success`). The registry `conditional_asset` (mode short_circuit) has the same shape, and two instances of it in one project fail with `conflicting node definitions ... _conditional` (the worker's report; for the component's owner). The `all_done` task lost its edges to the skipped tasks (`lost_ordering` on `task_7`): a skipped upstream skips any asset, so those edges cannot exist; the edge to the always-materialized task can. **Fix (run)**: `short_circuit.py: short_circuit_task` (always-yielded task spec + skippable marker spec; guarded assets depend on the marker, an `all_done` task on the task asset), `short_circuit.md` corrected, claims in `index.json`, test `test_short_circuit_decision_plus_marker_keeps_the_task_successful_and_skips_only_what_is_below`. The remaining `lost_ordering` of `task_7` after skipped tasks is inherent and stays reported. |
| `example_weekday_branch_operator` | **equivalent** (re-computed, run) | **harness bug** (fixed) | read + run: the header line `branch_true: replaced by asset `branch_true` (optional output of multi_asset `branch_on_monday`)` resolved to `branch_false`: `parse_header` skipped every backticked name equal to the task id (meant for the task's own name at the start of the line), so it fell through to the node name `branch_on_monday`, and two assets of that node resolve to the first one. Same for `branch_weekend` to `branch_mid_week`. The tasks and the "added ordering" differences were all this. **Fix**: `parse_header` reads the names after the mode word first (an asset named like the task counts there), and ignores the task's own name only before it; test `test_header_accounting_takes_an_asset_named_like_the_task_and_not_its_sibling_in_the_same_node`. Re-computed from the stored results: equivalent (thin). Classed `by-design-failure` by the harness (no environmental pattern matches), so the gate asked for a failure. |
| `pandas_xcom` | **equivalent** (re-computed, run) | **harness artefact** (fixed) | read + run, two causes. (1) values: Airflow's recorded XCom for a DataFrame is its serializer's encoded string (`pandas.core.frame.DataFrame@version=1(<hex>)`), the route's value is the frame's text: not comparable as JSON. **Fix**: such a record is `not-compared` with the reason.
