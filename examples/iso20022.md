# ISO 20022 Payment Parser — synthetic XML → flat transactions DataFrame

**Validated end-to-end** (pure Python). 10 alternating pacs.008 (credit transfer) + pacs.002 (status report) ISO 20022 XML messages → 10 flat transaction rows ready for warehouse / reconciliation.

```
iso20022_messages       ← synthetic_data_generator (iso20022_payments, 10 msgs)
       │
       └── payments_flat   ← iso20022_payment_parser
```

## Components covered (2)

| Component | What it does |
|---|---|
| [`synthetic_data_generator`](https://github.com/eric-thomas-dagster/dagster-component-templates/tree/main/assets/ai/synthetic_data_generator) | `schema_type: iso20022_payments` alternates between pacs.008 (FI-to-FI Customer Credit Transfer) and pacs.002 (Payment Status Report). Realistic IBANs, BICs, currencies. |
| [`iso20022_payment_parser`](https://github.com/eric-thomas-dagster/dagster-component-templates/tree/main/assets/transforms/iso20022_payment_parser) | Stdlib `xml.etree` parser. Auto-detects message type from XML namespace, strips namespaces for portable XPaths, runs the matching extractor. |

## Bugs surfaced fixing this demo

1. **Message-type detection mismatch**: the namespace `urn:iso:std:iso:20022:tech:xsd:pacs.008.001.08` was captured as the full versioned id (`pacs.008.001.08`), but the parser lookup was keyed by the short form `pacs.008`. Fixed in the component by truncating to first 2 segments.

## Supported message families

| ID | Name | Output |
|---|---|---|
| `pacs.008` | FI-to-FI Customer Credit Transfer | One row per `CdtTrfTxInf` |
| `pain.001` | Customer Credit Transfer Initiation | One row per transaction |
| `pacs.002` | Payment Status Report | One row per status |
| `camt.054` | Bank-to-Customer Debit/Credit Notification | One row per entry |

Other families fall back to a generic header-only extractor.

## Why ISO 20022 matters

ISO 20022 is replacing legacy SWIFT MT globally. SEPA, Fedwire, CHIPS, and most major clearing networks are on it now. Every fintech / treasury / payments operations pipeline ingests these XML envelopes for reconciliation, anomaly detection, regulatory reporting.
